# 課金の可視化とコスト予測（FinOps）

## 何を数えるか

| 費目 | 記録 | 単位と単価（rate_card・仮置き） |
|---|---|---|
| API 利用 | Kong の全要求（http-log → `usage-ingest` → `usage_event`） | 1 要求あたり：ゲートウェイ 0.02 円 ＋ MuleSoft 0.30 円（外部連携の経路）＋ 勘定系 0.05 円（Liberty に届く経路） |
| LLM | Agent の実行ごとのトークン数（`agent-usage` → `agent_run`・`usage_event`） | Claude Opus 5.5：入力 4・出力 20・キャッシュ読み込み 0.2・書き込み 5（USD／100 万トークン）× 為替 150 |
| インフラ | Railway の使用量 API（サービス・日ごとの vCPU・分、メモリ GB・分、外向き GB、ディスク） | vCPU・分 0.000463 USD、GB・分 0.000231 USD、外向き 0.05 USD／GB、ディスク 0.15 USD／GB・月（参考値） |
| 固定費 | 単価表の `FIXED:*`（月額） | MuleSoft・Kong のライセンス（デモは 0） |

1 要求の費用 = 該当する層の単価の和。固定費（ライセンス）と変動費（要求・トークン・使用量）を分け、二重に数えない。
単価・為替は仮置きで、ベンダーとの契約・請求書で照合して更新する（税は含まない）。

## 配賦（チャージバック）

`cost_center` で配賦先を部門・担当・月の予算に結び付ける。

| 配賦先 | 決め方 |
|---|---|
| 連携先（CONSUMER） | Kong の利用者（トークンの azp）。zengin-network → 決済事業部 など |
| AI Agent（AGENT） | Agent のクライアント（bank-agent → 業務企画部）。Agent が呼んだ勘定系の API と LLM の両方 |
| 経路（CHANNEL） | 利用者のない要求：画面（web）、MuleSoft からの勘定系の呼び出し（integration） |
| インフラ（INFRA） | Railway（システム部） |

配賦先のない要求は「未配賦」として表示する。予算のない配賦先は「予算なし」。

## 予測

```
月末予測 = 当月実績 ＋ 直近 7 日（今日を除く完了日）の日平均 ×（残り日数 ＋ 今日の残り 0.5 日）＋ 固定費
幅：下限 = 直近 30 日と 7 日の日平均の小さい方、上限 = 直近 7 日の最大日と日平均の大きい方
信頼度：完了日が 7 日未満は「低」、14 日未満は「中」、それ以上は「高」
急増：今日の費用が直近 7 日の日平均の 3 倍を超え、かつ 100 円を超える
```

過去の月は実績だけ（「確定」）。季節性・月末の集中（給与日・引落日）は直近 30 日の幅で目安を示す。データが少ない間は信頼度「低」を表示する。

## 予算と統制

| 状態 | 条件 | 対応 |
|---|---|---|
| 予算内 | 見込み < 予算の 80% | — |
| 注意 | 80% ≦ 見込み ≦ 100% | 画面に表示。担当に確認 |
| 超過見込み | 見込み > 予算 | 画面に表示。予算の見直しか利用の抑制 |
| 停止（hard stop） | 当月実績 ≧ 予算（hard_stop の配賦先だけ） | AI Agent の新しい実行を止める。重要業務の API（連携・画面）は止めない |

AI Agent はさらに 1 回の実行の費用の上限（既定 50 円）で打ち切る。予算は役席が画面から変更でき、変更はログに残る。

## 画面（コスト・課金・役席）

当月実績・月末の見込み（幅・信頼度）・予算の状況、費目別、部門別、配賦先別（急増・停止）、日別の推移、API 別（要求数・平均遅延・5xx）、
インフラ（サービス別）、AI アシスタントの実行の追跡、単価表。Railway の使用量は夜間バッチ（`INFRA_COST_SYNC`）か画面のボタンで取り込む
（`RAILWAY_API_TOKEN`：Railway のアカウント／ワークスペースのトークンが必要。未設定なら取り込まない）。

## 照合

月次で、Anthropic の請求（Usage and Cost）と `usage_event` の LLM 分、Railway の請求とインフラ分を照合し、差があれば単価表を直す。
Railway の見積もり API（estimatedUsage）はワークスペースのトークンでのみ使えるため、このサンプルは日次の使用量から自前で予測する。
